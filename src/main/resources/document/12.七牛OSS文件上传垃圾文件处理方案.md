# 七牛 OSS 文件上传垃圾文件处理方案

## 问题背景

在实现文件上传功能（如用户头像、管理员头像、简历附件等）时，面临一个核心问题：

**用户上传了文件但未提交保存，会导致 OSS 中产生大量"孤儿文件"（垃圾文件）**

### 典型场景

1. 用户在修改头像页面选择了一张图片；
2. 前端立刻调用 `/uploadAvatar` 接口，将文件上传到七牛 OSS；
3. 后端返回文件访问 URL：`http://cdn.xxx.com/dev/user/user_avatar/10086/2025/12/31/abc123.jpg`；
4. 前端显示预览效果；
5. **用户看了一眼觉得不满意，直接关闭页面 / 刷新 / 点击取消按钮**，未点击"保存"；
6. 结果：
   - 数据库中 `user_image` 字段仍然是旧头像 URL；
   - 七牛 OSS 中已经存在 `abc123.jpg` 文件，但永远不会被使用；
   - 随着时间推移，OSS 中会堆积大量这样的垃圾文件，浪费存储空间、增加成本。

---

## 解决方案对比

### 方案 A：数据库记录 + 引用计数（实时高效）

#### 核心思路

1. 上传时在数据库中创建一条"文件记录"（包含 key、URL、状态、上传时间等）；
2. 业务表（admin / user）不直接存 URL，而是存"文件记录的 ID"；
3. 提交时才"确认"文件记录（状态从"临时"改为"已确认"）；
4. 定时任务清理"临时状态 + 超过 24 小时未确认"的文件记录。

#### 数据库设计

**文件表（oss_file）：**
```sql
CREATE TABLE oss_file (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    file_key VARCHAR(500) NOT NULL COMMENT '七牛 key',
    file_url VARCHAR(500) NOT NULL COMMENT '访问 URL',
    system_type VARCHAR(50) COMMENT '系统类型：admin/user/ad_monitor',
    business_type VARCHAR(50) COMMENT '业务类型：avatar/resume等',
    owner_id BIGINT COMMENT '拥有者ID',
    is_private TINYINT DEFAULT 0 COMMENT '是否私有',
    status TINYINT DEFAULT 0 COMMENT '0-临时 1-已确认',
    upload_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    deleted TINYINT DEFAULT 0
);
```

**业务表改造：**
```sql
-- 管理员表
ALTER TABLE admin ADD COLUMN avatar_file_id BIGINT COMMENT '头像文件ID，关联 oss_file.id';

-- 用户表
ALTER TABLE user ADD COLUMN avatar_file_id BIGINT COMMENT '头像文件ID，关联 oss_file.id';
```

#### 优缺点

**优点：**
- ✅ 前端上传即刻预览，用户体验好；
- ✅ 提交时才"转正"，逻辑清晰；
- ✅ 可以精确控制哪些文件是垃圾、哪些是有效的；
- ✅ 定时任务只清理"临时 + 超时"的，效率高；
- ✅ 可以扩展"文件管理"功能（用户查看自己的所有文件、删除历史头像等）。

**缺点：**
- ❌ 需要新增文件表 + 改造业务表结构；
- ❌ 增加了一定的开发成本和维护复杂度；
- ❌ 仍然会有短暂的存储浪费（24 小时内未确认的文件）。

---

### 方案 B：前端暂存 + 提交时才上传（最省存储，推荐）⭐

#### 核心思路

1. 用户选择文件后，**前端不调用后端上传接口**；
2. 使用 `FileReader` 或 `URL.createObjectURL` 在本地生成预览（Base64 / Blob URL）；
3. 用户点击"保存"时，**前端才调用上传接口**，上传成功后拿到 URL；
4. 前端再将 URL + 其他表单数据一起提交给后端保存；
5. 用户点击"取消"或刷新页面 → 文件还在本地，没有传到 OSS，不会产生任何垃圾文件。

#### 实现要点

**前端实现（以 React 为例）：**

```typescript
const [previewUrl, setPreviewUrl] = useState<string>('');
const [selectedFile, setSelectedFile] = useState<File | null>(null);

// 用户选择文件 → 本地预览
const handleFileChange = (e: React.ChangeEvent<HTMLInputElement>) => {
  const file = e.target.files?.[0];
  if (file) {
    setSelectedFile(file);
    // 生成本地预览 URL
    const url = URL.createObjectURL(file);
    setPreviewUrl(url);
  }
};

// 用户点击"保存" → 先上传文件，再提交表单
const handleSave = async () => {
  if (!selectedFile) return;

  // 1. 上传文件到七牛
  const formData = new FormData();
  formData.append('file', selectedFile);
  
  const uploadRes = await axios.post('/admin/file/uploadAvatar', formData);
  const avatarUrl = uploadRes.data.data; // 拿到 URL

  // 2. 提交表单（带上文件 URL）
  await axios.post('/admin/admin/update', {
    adminId: currentAdminId,
    adminImage: avatarUrl,
    // ... 其他字段
  });

  message.success('保存成功');
};

// 用户点击"取消" → 清空预览，不做任何上传
const handleCancel = () => {
  setSelectedFile(null);
  setPreviewUrl('');
  URL.revokeObjectURL(previewUrl); // 释放 Blob URL
};
```

**后端实现：**

后端保持现有的上传接口不变，只负责：
- 接收 `MultipartFile`，上传到七牛 OSS；
- 返回文件访问 URL。

不需要任何"临时 → 转正"的逻辑，不需要新增表，简单直接。

#### 优缺点

**优点：**
- ✅ **完全不产生垃圾文件**，存储最干净；
- ✅ **后端逻辑最简单**，不需要新增表、不需要定时任务；
- ✅ **数据库结构不用改**，业务表直接存 URL 即可；
- ✅ 适合毕设项目，开发成本低、易于维护。

**缺点：**
- ❌ 用户点击"保存"时需要等待上传完成，大文件会有一定延迟（但对于头像等小文件，影响不大）；
- ❌ 刷新页面后预览会丢失（除非做 localStorage 缓存）。

### 方案 C：OSS 生命周期策略 + 临时目录（零代码维护）

#### 核心思路

1. 上传时将文件放到"临时目录"（如 `dev/admin/temp/avatar/...`）；
2. 在七牛控制台配置"对象生命周期管理规则"：临时目录下的文件，超过 1 天自动删除；
3. 用户提交时，后端将文件从临时目录"复制"到正式目录，删除临时文件；
4. 用户取消或刷新 → 临时文件由七牛自动清理，后端零维护成本。

#### 七牛控制台配置

1. 进入"对象存储 → 空间设置 → 生命周期管理"；
2. 新建规则：
   - **前缀**：`dev/temp/` 或 `*/temp/`
   - **动作**：超过 1 天后删除
3. 保存规则。

#### 后端实现要点

**上传到临时目录：**
```java
private String buildTempKey(...) {
    return String.format("%s/%s/temp/%s/%d/%d/%02d/%02d/%s%s",
            env, systemType.getDir(), businessType.getDir(), ownerId, ...);
}
```

**用户保存时，复制到正式目录：**
```java
public void confirmUpload(String tempUrl) {
    String tempKey = extractKeyFromUrl(tempUrl);
    String formalKey = tempKey.replace("/temp/", "/");
    
    BucketManager bucketManager = new BucketManager(auth, cfg);
    bucketManager.copy(bucket, tempKey, bucket, formalKey, true);
    bucketManager.delete(bucket, tempKey);
}
```

#### 优缺点

**优点：**
- ✅ 前端上传即刻预览，体验好；
- ✅ **后端零维护成本**，七牛自动清理临时文件；
- ✅ 逻辑清晰，临时 / 正式目录分离明确。

**缺点：**
- ❌ 需要在七牛控制台配置生命周期规则（一次配置，但对新人有一定门槛）；
- ❌ 复制文件有额外的 API 调用成本（但很低）。

## 最终选择：方案 B（前端暂存 + 提交时上传）⭐

### 选择理由

1. **开发成本最低**：不需要新增表、不需要定时任务、不需要配置七牛规则，后端逻辑最简单；
2. **存储最干净**：完全不产生垃圾文件，OSS 中只有"真正保存过的文件"；
3. **适合毕设项目**：作为学习型开源项目，方案 B 易于理解、易于维护，对后续贡献者友好；
4. **对小文件友好**：头像、小图片上传速度很快（几百 KB），用户等待时间可接受；
5. **数据库结构简单**：业务表直接存 URL，不需要额外关联表，符合 KISS 原则。

### 适用场景

- ✅ 头像上传（管理员头像、用户头像）
- ✅ 广告图片、公告配图（小于 5MB）
- ⚠️ 简历附件（如果是大文件，可能需要考虑方案 A 或 C，避免用户长时间等待）

### 后续优化方向

如果未来遇到以下情况，可以考虑升级方案：

1. **大文件上传场景增多**（如视频简历、大型作品集）→ 升级为方案 A（数据库记录 + 引用计数）；
2. **存储成本敏感 + 用户量大**（每天上万次上传）→ 升级为方案 C（OSS 生命周期策略）；
3. **需要文件管理功能**（用户查看历史文件、批量删除）→ 升级为方案 A。

## 技术实现要点

### 前端关键代码（React + TypeScript 示例）

```typescript
import { useState } from 'react';
import axios from 'axios';
import { message } from 'antd';

const AvatarUpload = () => {
  const [previewUrl, setPreviewUrl] = useState<string>('');
  const [selectedFile, setSelectedFile] = useState<File | null>(null);
  const [uploading, setUploading] = useState(false);

  // 选择文件 → 本地预览
  const handleFileChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const file = e.target.files?.[0];
    if (!file) return;

    // 文件类型校验
    if (!file.type.startsWith('image/')) {
      message.error('请选择图片文件');
      return;
    }

    // 文件大小校验（限制 5MB）
    if (file.size > 5 * 1024 * 1024) {
      message.error('图片大小不能超过 5MB');
      return;
    }

    setSelectedFile(file);
    const url = URL.createObjectURL(file);
    setPreviewUrl(url);
  };

  // 保存 → 先上传，再提交
  const handleSave = async () => {
    if (!selectedFile) {
      message.warning('请先选择文件');
      return;
    }

    setUploading(true);
    try {
      // 1. 上传到七牛
      const formData = new FormData();
      formData.append('file', selectedFile);

      const uploadRes = await axios.post('/admin/file/uploadAvatar', formData, {
        headers: { 'Content-Type': 'multipart/form-data' }
      });

      const avatarUrl = uploadRes.data.data;

      // 2. 提交表单更新头像
      await axios.post('/admin/admin/update', {
        adminId: currentUser.id,
        adminImage: avatarUrl
      });

      message.success('头像更新成功');

      // 3. 释放 Blob URL
      URL.revokeObjectURL(previewUrl);
      setSelectedFile(null);

    } catch (error) {
      message.error('上传失败');
    } finally {
      setUploading(false);
    }
  };

  // 取消
  const handleCancel = () => {
    if (previewUrl) {
      URL.revokeObjectURL(previewUrl);
    }
    setSelectedFile(null);
    setPreviewUrl('');
  };

  return (
    <div>
      <input type="file" accept="image/*" onChange={handleFileChange} />
      {previewUrl && <img src={previewUrl} alt="预览" />}
      <button onClick={handleSave} disabled={uploading}>
        {uploading ? '上传中...' : '保存'}
      </button>
      <button onClick={handleCancel}>取消</button>
    </div>
  );
};
```

### 后端关键代码（Spring Boot + 七牛 SDK）

```java
@RestController
@RequestMapping("/admin/file")
public class AdminFileController {

    @Autowired
    private OssService ossService;

    @Autowired
    private AdminService adminService;

    /**
     * 上传管理员头像
     */
    @PostMapping("/uploadAvatar")
    public BaseResult<String> uploadAvatar(
            @AuthenticationPrincipal SecurityUser securityUser,
            @RequestPart("file") MultipartFile file) {

        Long adminId = securityUser.getUserId().longValue();

        // 上传到七牛公开空间
        String url = ossService.upload(
                file,
                OssSystemTypeEnum.ADMIN,
                OssAdminBusinessTypeEnum.ADMIN_AVATAR,
                adminId,
                false // 头像放公开空间
        );

        return BaseResult.ok(url);
    }
}
```

## 总结

**方案 B（前端暂存 + 提交时上传）是当前项目最合适的选择**，理由是：

1. **开发成本低**：后端保持现有上传接口即可，不需要新增表、定时任务；
2. **存储最干净**：完全不产生垃圾文件；
3. **适合毕设项目**：简单、易懂、易维护，符合学习型开源项目定位。

将来如果遇到大文件上传场景、或者需要文件管理功能，可以平滑升级为方案 A 或 方案 C。
